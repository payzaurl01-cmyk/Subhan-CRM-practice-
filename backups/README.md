# Local live database snapshot

`livedatabase 11-4-2026.crm-records-only.sql` is an immediate, read-only export of the 289 rows in `public.crm_records` on 4 November 2026. It is a **partial** snapshot for the CRM record table, not a full database backup. Its matching `.sha256` file verifies the local export. It requires the target table schema to exist and should be restored to an empty table in an isolated target. Do not run it as a normal Supabase migration.

Run `./backup-live-database.ps1` from PowerShell with PostgreSQL 17 or newer client tools installed. The script prompts for the Supabase database password, creates `livedatabase 11-4-2026.sql`, and writes a SHA-256 checksum. It performs a read-only `pg_dump` of the entire database, including schema and data, without using Supabase's backup feature. The SQL and checksum are ignored by Git because they contain sensitive live data.

Use the existing database password set when the project was created. The dashboard shows a password placeholder, not the current password. Do not put the password into source control or paste it into the command line. Resetting it would affect existing clients, so this script never resets it. If direct IPv6 connections are unavailable, supply the Session Pooler host, port, and username shown in the dashboard with `-HostName`, `-Port`, and `-Username`.

Keep this file outside `supabase/migrations`: a full snapshot is for deliberate recovery, not an automatic migration. To restore, first create an isolated target PostgreSQL 17/Supabase project and use `psql -v ON_ERROR_STOP=1 -f 'livedatabase 11-4-2026.sql'` with its connection settings. Verify users, CRM records, and storage metadata before considering a production restore. Database SQL does not contain Storage object bytes; download those separately if the project has uploaded files. Restoring into an existing Supabase project may need adjustments for objects that Supabase manages, so test the SQL against an isolated target first.
